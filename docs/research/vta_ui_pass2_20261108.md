# UI Pass 2 — deployed for owner interface review

This is the approved interface reorganization, not a broader QA milestone or release. Owner assignment/suppression UI flows have narrow manual acceptance; unrelated product workflows are not declared manually validated. David will review the consolidated interface and decide what needs adjustment.

## Presentation changes

- Current Frame Review is **Character Assignment**, retaining its underlying class/operator identities. Character selection/create/management and Candidate selection/actions now share that section. Repeat Last Assignment is directly available there.
- Assignment marks show **(Character display name)**, following the currently selected batch destination. With no destination they say **(Choose Character)**. No target is secretly captured when marking; the existing assignment semantics are unchanged. Marked assignment boxes have an inset outline; suppression has a cross and **[Suppress]** text. Normal candidates retain their existing appearance and provenance. Pixel appearance awaits owner review.
- Removed the standalone Mark Active Character heading. Occluded, Not Visible and No Valid Candidate remain separate existing actions within Character Assignment: **preserved but intentionally unresolved for later review**.
- Workspace has one Open VTA Workspace action and collapsed **VTA Scenes**, **Camera and Playback**, and bottom **Details** drawers. Camera and Playback contains Snap, Match FPS and Camera Depth; its last drawer is **Advanced**, with the existing calibration and Automatic Depth checkbox. Fixed/Automatic Depth behavior is unchanged. Passive frame/count/FPS information is in Details; critical errors/recovery remain outside it.
- The final major top-level section is **VTA Resources**, with Logs and Support, Version Information, read-only Core / Runtime Information, and Credits. Version data includes product build, protocol, supported ProjectState version and deployment folder identifier. It is cached, performs no engine query, and reports unavailable runtime details safely. Copy Version Info was optional and was not added.
- Credits retain BlendCap's prominent foundation/FK contribution and donation policy, acknowledge Blender and the known SAM model capabilities, and point to Notices. This is not the definitive licensing/attribution audit.
- **Export / Retarget** combines the existing BVH controls and retargeting controls. It calls the same operator paths; bake, timers, popup and animation behavior were not changed.
- Both the preview and timeline **VTA Commands** menus now explicitly contain Retry Reconciliation, even when review data is unavailable. The operator is disabled without a recoverable pending request, preventing an empty retry from creating misleading recovery feedback. Actual recovery logic is unchanged.
